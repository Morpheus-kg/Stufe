# Изменения и расширения сверх контрактов v1 и v2

Данный документ описывает весь функционал, архитектурные доработки и изменения, которые были внедрены в проект **German Trainer** сверх исходных спецификаций (`German Trainer — CONTRACT v1.md` и `CONTRACT_v2.md`).

---

## 1. Многопользовательский режим и разграничение прав (RBAC)

Контракты v1 и v2 предполагали однопользовательскую систему с единым паролем `APP_PASSWORD`. Для поддержки нескольких учетных записей и роли администратора реализовано следующее:

### 1.1. База данных
* **Миграция `server/migrations/002_users.js`**:
  Создаёт таблицу `users`:
  ```sql
  CREATE TABLE users (
    id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(50) NOT NULL UNIQUE,
    role ENUM('admin','user') NOT NULL DEFAULT 'user',
    password_hash VARCHAR(255) NOT NULL,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
  ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
  ```

### 1.2. Безопасность и хэширование (без новых npm-пакетов)
* Реализовано криптографическое хэширование паролей с солью на базе встроенного модуля Node.js `crypto.scrypt` с защитой от тайминг-атак (`crypto.timingSafeEqual`).
* Формат хранения хэша: `<salt_hex>:<derived_key_hex>`.

### 1.3. Расширение сессионных токенов (`server/auth.js`)
* Токен HMAC cookie `sid` расширен:
  Формат: `v1.<expMs>.<nonce>.u<userId>.<role>.<hmac_signature>`.
* Добавлены функции:
  * `tokenClaims(token)` — безопасное извлечение `userId` и `role`.
  * `requireAdmin(req, res, next)` — middleware проверки прав администратора.
* **100% обратная совместимость**: если в базе нет пользователей, сервер автоматически работает по `APP_PASSWORD`, а входящий пользователь получает роль `admin`.

### 1.4. API администратора (`server/routes/admin.js`)
* `GET /api/admin/users` — список пользователей (только для `admin`).
* `POST /api/admin/users` — создание нового пользователя с логином, паролем и ролью (`admin`/`user`).
* `PUT /api/admin/users/:id` — обновление роли или сброс пароля.
* `DELETE /api/admin/users/:id` — удаление пользователя (с защитой от удаления последнего администратора).

### 1.5. UI интерфейс администратора (`public/js/views/admin.js`)
* Экран `#/admin` (пункт в меню «Ещё»):
  * Просмотр списка пользователей с их ролями и датами регистрации.
  * Быстрая смена пароля по кнопке 🔑.
  * Удаление аккаунта с подтверждением.
  * Форма добавления нового пользователя.
  * Экран блокировки при попытке входа без прав администратора.

## 2. Пользовательский интерфейс и мобильный UX

### 2.1. Переключение темы (Светлая / Тёмная / Системная)
* В верхний правый угол добавлена фиксированная кнопка `#theme-btn` с циклическим переключением: `☀️ Светлая` → `🌙 Тёмная` → `🌓 Авто` (сохраняется в `localStorage`).
* Переработана цветовая палитра `public/css/app.css`:
  * Отказ от стандартного синего («корпоративного ИИ») цвета.
  * Введена природная лесная палитра с основным акцентом `--primary: #2e7d52` (светлая) и `--primary: #4caf7d` (тёмная).
  * Плавные CSS-переходы (`transition: background .2s, color .2s`).

### 2.2. Новый экран «Практика» (`public/js/views/practice.js`)
* В контракте v2 все режимы практики были спрятаны во всплывающем меню нижней панели.
* Реализован полноценный экран `#/practice` со структурированными карточками и категориями:
  * **Основное**: Тексты, Аудирование, Числа на слух, Перевод.
  * **Речь и письмо**: Говорение, Письмо, Пересказ.
  * **Дополнительно**: Лаборатория текста.
* Карточки адаптированы под мобильные тапы, имеют физический отклик (`transform: scale(0.97)`) и контрастные иконки.

### 2.3. Редизайн экрана «Статистика» (`public/js/views/stats.js`)
* Убрано навязчивое повторение подписи «30 дней» во всех заголовках.
* Добавлена кольцевая SVG-диаграмма удержания знаний (Retention Ring) без подключения сторонних библиотек.
* Серия дней выделена крупной типографикой с подсказкой статуса на сегодня.
* Блок «Карточки» реорганизован в сетку из 6 компактных плиток.

## 3. Выбор нейросети и уровня при генерации слов

* В экран `#/staging` (`public/js/views/staging.js`) добавлены элементы управления генерацией:
  * **Уровень**: селектор `B1`, `B2`, `C1`.
  * **Нейросеть**: выпадающий список провайдеров (`Авто`, `Groq`, `Gemini`, `OpenRouter`), который динамически опрашивает `GET /api/ai/providers` и показывает только доступные в данный момент провайдеры.
  * Выбранные параметры прозрачно передаются в `generateWords(...)`.

## 4. Стабилизация и совместимость AI-клиента

* **Флаг `supportsJsonMode` (`server/ai/providers.js`)**:
  Google Gemini через OpenAI-совместимый эндпоинт возвращал ошибку `invalid json` при передаче `response_format: { type: 'json_object' }`. Добавлено разделение: `response_format` отправляется только тем провайдерам, которые полноценно его поддерживают (Groq, OpenRouter).
* **Модели под ключ пользователя**:
  Зафиксированы модели, реально поддерживаемые подключенными ключами:
  * Groq: `openai/gpt-oss-120b`, `openai/gpt-oss-20b`, `whisper-large-v3-turbo`.
  * Gemini: `gemini-3.6-flash`, `gemini-3.5-flash-lite`.

## 5. Готовность к облачному деплою (Railway / Docker / PaaS)

* **`railway.json`**:
  Спецификация развертывания под Railway с проверкой состояния `healthcheckPath: /api/health` и политикой перезапуска при сбоях.
* **`nixpacks.toml`**:
  Декларативная сборка окружения с Node.js 20 и установкой production-зависимостей (`npm install --production`).
* **IPv4 привязка для локального Windows/XAMPP**:
  Исправлена проблема разрешения `localhost` в IPv6 (`::1`), из-за которой Node.js получал `EACCES` при подключении к MariaDB. `MYSQLHOST` переведен на `127.0.0.1`.
